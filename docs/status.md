# Status

What works today and what is experimental.

| Feature                                               | Status          | Notes                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `factory ship` pipeline (PLAN → BUILD → CHECK → SHIP) | ✅ Working      | Covered by an end-to-end pipeline integration test                                                                                                                                                                                                                            |
| `factory triage` (queue from open issues)             | ✅ Working      | Finishes started decomposed parents before starting new ones (explicit `factory:order` wins).                                                                                                                                                                                 |
| `factory run` (parallel lanes)                        | ✅ Working      | Merges are serialized per lane via a merge-wait step                                                                                                                                                                                                                          |
| `factory land` / auto-merge                           | ✅ Working      | Auto-merge is **off by default**; turn it on with `FACTORY_MERGE=1`, `run.merge.auto: true` or `--auto-merge`. Land syncs a BEHIND or conflicting PR onto current main and merges only a CI-green synced head. Add `FACTORY_MERGE_ADMIN=1` only when admin bypass is intended |
| `factory supervise` (multi-window unattended runs)    | ✅ Working      | Waits for usage headroom, runs the queue, repeats until drained                                                                                                                                                                                                               |
| Usage-cap watchdog (`factory usage`, stop-at-cap)     | ✅ Working      | Claude 5-hour and weekly windows vs. cap (Claude models only); lanes stop at the cap. When PLAN and BUILD use a harness with no usage signal (codex-cli, opencode) it logs `usage-unavailable` "usage watchdog not available for this agent" and does not gate                |
| Codex worker builds (`codex exec`)                    | ✅ Working      | Used for the `build_codex` route                                                                                                                                                                                                                                              |
| Claude models via the Claude CLI (`claude -p`)        | ✅ Working      | TRIAGE and PLAN route through the model router; the boss tier starts with `claude-opus-5`, then local models                                                                                                                                                                  |
| Harness dispatch (per-model provider adapters)        | ✅ Working      | Each model declares a `harness` in `defaults.ts`: `claude-cli`, `codex-cli`, `ollama-http`, `ollama-agentic`, `opencode`, `pi`; repos can declare `command` harnesses                                                                                                         |
| GPT worker models via the Codex CLI                   | ✅ Working      | `gpt-5.6-terra` (plan=high / build=medium) → `gpt-5.6-sol` → `gpt-5.1-codex`, dispatched through the `codex-cli` harness                                                                                                                                                      |
| Local Ollama + OpenCode models                        | ⚠️ Experimental | Harnesses are contract-tested, but real-run behavior is unverified — expect failover to a cloud model                                                                                                                                                                         |
| Pi harness (DeepSeek via OpenRouter)                  | ⚠️ Experimental | PLAN, CHECK and commit-only BUILD; pin-only, needs `FACTORY_EXPERIMENTAL=1`; contract-tested and adapter-smoked, real-run behavior unverified                                                                                                                                 |
| Provider failover (`models.providerOrder`)            | ✅ Working      | A capped, failing or signed-out provider fails over to the next subscription provider for the phase, never to a metered (API-key) one. `factory status --json` shows providers and alerts                                                                                     |
| Queue claims (GitHub labels)                          | ✅ Working      | A claim holds a lease renewed by heartbeat. Expired and dead claims are reaped every cycle, and a run that loses its lease stops before push, PR or merge                                                                                                                     |
| Prompt evals (`npm run eval`)                         | ✅ Working      | Deterministic stub subset runs in CI on every PR; weekly real run checks prompt/constitution/skill regressions under pinned model IDs                                                                                                                                         |
| Cost tracking (`factory cost`)                        | ✅ Working      | Per-task tokens and cost logged to `.factory/state/costs.jsonl`                                                                                                                                                                                                               |
| Constitutions + checker rework loop                   | ✅ Working      | Up to 3 rework rounds with dispute resolution                                                                                                                                                                                                                                 |
| Server (`packages/server`)                            | ✅ Working      | Loopback `GET /events` relays the lane lifecycle bus as SSE (`Last-Event-ID` resume via a bounded replay ring); `POST /repos/:owner/:repo/lanes/:laneId/pause` pauses a lane. No auth.                                                                                        |

See the [README](../README.md) for Quick Start, and [agents.md](agents.md) for the supported coding agent CLIs.
